# Сообщение для Telegram — изменение контракта 25.10.2026

Команда, согласовано необязательное поле верхнего уровня JSON: `render_mode`.
Допустимы только строки `"2d"` и `"3d"`. Если поля нет, значение по умолчанию —
`"2d"`: все старые JSON продолжают работать. `"4d"`, null и другие значения
должны давать SpecError с указанием render_mode и допустимых вариантов.

A: добавь поле в Spec и проверку режима. `parse_spec` принимает `"3d"`,
а `render_video` для него пока бросает NotImplementedError, без создания 2D-видео.
Для режима 2D остаются текущие сцены text/image/chart и MP4 1080×1920, 30 fps.

B: показывай NotImplementedError в интерфейсе как понятное сообщение о том,
что 3D-рендер пока не реализован; приложение должно оставаться работоспособным.

C: обнови system prompt с этим полем. По умолчанию используй 2D; модель может
вернуть JSON без render_mode. Режим 3D допустим при явном запросе пользователя.
Сигнатуры публичного API и поля сцен сохраняются.

D: добавлены тесты отсутствующего режима, явных 2d/3d, неверного 4d и других
неподдерживаемых значений, отказа 3D-рендера и интеграции старых JSON.
В изолированной копии с backend A (`594174d`) и C из main прошли все 40 тестов,
включая старые JSON и реальные MP4 на 3/30 секунд. Тестовые PR #3/#4 остаются
draft до включения A в main. Контракт и зависимости уже в main через PR #2.

Blender/moderngl пока не выбирали. После выбора D добавит нужные зависимости
и проверит размер полной папки PyInstaller-сборки. Канонический контракт — AGENTS.md.
